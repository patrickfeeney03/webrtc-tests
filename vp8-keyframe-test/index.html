VP8 keyframe request test

Self-call on this device using VP8. Every 5 seconds the receiving side asks the sender for a keyframe (a PLI, the same request the other side of a real call sends) and the page counts how many keyframes the encoder actually produces.

How to run it
  1. Tap Start and allow the camera.
  2. Stay on this page for about 30 seconds (switching tabs or apps pauses the camera), then screenshot the text below the videos.
  3. To compare against the software encoder (Chrome on Android or desktop): open chrome://flags, set Hardware-accelerated video encode to Disabled, relaunch Chrome, and run the test again. The encoder line should then say libvpx. Set the flag back to Default afterwards.
How to read the result
  • encoder: the encoder Chrome picked. NdkVideoEncodeAccelerator(…) is the phone's hardware encoder, libvpx is software.
  • PLIs received by sender: keyframe requests that reached the sender. It should go up by about one every 5 seconds.
  • requests answered: keyframes the encoder produced in response. A healthy encoder keeps up with the requests sent, give or take one.
  • How the video looks doesn't tell you anything here. A self-call loses nothing, so missing keyframes never show on screen.
  • On iOS the encoder name isn't reported and there's no hardware flag to switch, so only the counts are useful there.
